# AGENT.md

คู่มือสำหรับ AI agent ที่จะเข้ามาศึกษา ดูแล แก้ไข หรือขยายระบบบริหารแผนพัฒนาท้องถิ่น 5 ปี เทศบาลนครนครสวรรค์

เอกสารนี้เป็นจุดเริ่มต้นแบบลงมือทำได้ทันทีสำหรับ agent รุ่นถัดไป อ่านไฟล์นี้ก่อนแก้โค้ด แล้วค่อยเปิดเอกสารละเอียดใน `docs/` และไฟล์ source ที่เกี่ยวข้อง

## 1. ภาพรวมระบบ

ระบบนี้เป็นเว็บแอปสำหรับบริหารข้อมูลแผนพัฒนาท้องถิ่น พ.ศ. 2566-2570 ของเทศบาลนครนครสวรรค์ โดยย้ายข้อมูลจาก Excel workbook ทางราชการมาเก็บในฐานข้อมูล PostgreSQL และแสดงผลผ่าน dashboard, รายการโครงการ, รายละเอียดโครงการ, ครุภัณฑ์, หน้าเกี่ยวกับระบบ, คู่มือ, import/export, audit log และระบบผู้ดูแล

กลุ่มผู้ใช้หลัก:

- ผู้ใช้ทั่วไป: อ่าน dashboard, โครงการ, ครุภัณฑ์ ได้แบบ read-only
- ผู้ดูแลระบบ: login แล้วเพิ่ม แก้ไข ลบ เปลี่ยนสถานะ import/export จัดการผู้ใช้ ดู audit log และจัดการโครงสร้างแผน

ปีงบประมาณหลักของระบบ:

- 2566
- 2567
- 2568
- 2569
- 2570

ลำดับข้อมูลเชิงโครงสร้าง:

```text
Strategy -> Tactic -> Plan -> Project -> Project Budget by Fiscal Year
```

ฐานข้อมูลเป็น Neon PostgreSQL ใช้ server-side SQL ผ่าน `@neondatabase/serverless` เท่านั้น ห้ามนำ `DATABASE_URL` ไปไว้ฝั่ง browser หรือ env ที่ขึ้นต้นด้วย `VITE_`

## 2. เทคโนโลยีหลัก

- Framework: TanStack Start + TanStack Router
- UI: React 19
- Build: Vite 7 ผ่าน `@lovable.dev/vite-tanstack-config`

## 6. Data Model

Core tables:

- `strategies`
- `tactics`
- `plans`
- `projects`
- `project_budgets`
- `equipment`
- `admin_users`
- `project_annotations`
- `sheet_metadata`
- `document_metadata`
- `import_batches`
- `staging_projects`
- `departments`
- `audit_events`

Project status values:

```ts
type Status =
  | "not_set"
  | "planning"
  | "in_progress"
  | "completed"
  | "cancelled";
```

Budget storage:

- Project budgets are rows in `project_budgets`.
- Each budget row has `project_id`, `year`, `amount`, and optional `ordinance_amount`.
- UI expects budget amounts to be raw baht values, not thousands.
- `formatBaht()` in `src/lib/mock-data.ts` is the central formatter.
- Do not reintroduce compact display that turns `250000` into `250 พัน`; values under 1,000,000 should display as full baht numbers where compact formatting is used.

Equipment storage:

- Equipment has one numeric column per fiscal year:
  - `budget_2566`
  - `budget_2567`
  - `budget_2568`
  - `budget_2569`
  - `budget_2570`

Annotation storage:

- `project_annotations.project_id` is the trusted link between a note/text box and a project.
- Do not fall back to `source_row` matching in user-facing queries unless explicitly designing a review workflow.
- Current project list/detail surfaces only explicitly linked annotations.
- Project list annotation search is intentionally smart-normalized in `src/lib/server-fns.ts`: Thai digits are converted to Arabic digits, zero-width characters are removed, and compact matching ignores whitespace, punctuation, and symbols. This is required so queries like `ครั้งที่ 2/2568` match text boxes extracted as `ครั้งที่ 2 / 2568` or split across OOXML text runs.
- Annotation search haystacks include both `raw_text` and structured fields such as `amendment_type`, `amendment_number`, `amendment_year`, `target_plan`, `target_ref`, and `funding_source`.

Public visibility:

- Public users see read-only routes and controls only.
- When `publish_status` exists, public project/equipment reads show `reviewed` and `published` rows. Admin viewers see all rows.
- Current code falls back to all rows if no reviewed/published rows exist, so the public portal does not appear empty during setup. Revisit this before strict launch.

## 7. Server Functions and API Pattern

Client and route components should import wrapper functions/types from `src/lib/api.ts`.

Example:

```ts
import { apiGetProjects, apiPatchProjectStatus } from "@/lib/api";
```

Database reads/writes live in `src/lib/server-fns.ts` as TanStack Start `createServerFn` handlers.

Pattern:

```ts
export const serverSomeMutation = createServerFn({ method: "POST" })
  .handler(async ({ data }) => {
    const session = await requireAdmin();
    const sql = getSql();
    // write DB
    // insert audit event
  });
```

Rules:

- Read-only public queries do not call `requireAdmin()`.
- Any create/update/delete/import/status/user/hierarchy mutation must call `requireAdmin()`.
- Important mutations should write their own audit record server-side.
- Do not rely on client-side audit logging for important writes.
- Use parameterized tagged SQL from Neon driver. Do not concatenate SQL strings with user input.
- For TanStack server function errors, prefer throwing `Response` with JSON body and status code instead of throwing `Error`, because serialized server errors can break in some deployments.

`src/lib/api.ts` is also the main type catalog. Update it when changing return shapes.

## 8. Authentication and Authorization

Auth files:

- `src/lib/auth.ts`: `serverLogin`, `serverLogout`, `serverGetSession`
- `src/lib/session.server.ts`: session config and `requireAdmin()`
- `src/hooks/use-auth.ts`: client hook around server auth functions
- `src/routes/login.tsx`: login page
- `src/components/AppLayout.tsx`: hides admin navigation for public users

Session:

- Cookie name: `admin_session`
- Password from `SESSION_PASSWORD`
- Minimum password length enforced in config: 32 characters
- Cookie is httpOnly, sameSite lax, secure in production

Admin users:

- Stored in `admin_users`
- `username`
- `password_hash`
- `created_at`

Login behavior:

- Username is normalized to lowercase and stripped after `@`.
- Password hash uses bcryptjs.
- Failed attempts are rate-limited in memory: 5 failures per username per 60 seconds.
- Login/logout write audit events.
- Production setup problems are returned as safe diagnostic codes, then translated on `/login`: `DATABASE_URL_MISSING`, `SESSION_PASSWORD_MISSING`, `ADMIN_USERS_TABLE_MISSING`, and `ADMIN_USERS_NOT_SEEDED`.
- Do not replace these setup diagnostics with raw thrown errors; raw Vercel/Neon errors can expose implementation details and are harder for officers to act on.

Authorization rule:

- Hiding a button is not security.
- Server mutations must call `requireAdmin()` even if UI already hides controls.

## 10. Query and Cache Conventions

TanStack Query is used throughout route pages.

Common query keys:

- `["dashboard"]`
- `["projects", filters...]`
- `["project", id]`
- `["equipment", filters...]`
- `["session"]`
- `["users"]`
- `["audit"]`

After mutations, invalidate affected queries. Examples:

- Project create/update/delete/status:
  - invalidate projects list
  - invalidate dashboard
  - invalidate specific project detail when relevant
- Equipment mutations:
  - invalidate equipment list
  - invalidate dashboard if budget totals depend on it
- Auth mutations:
  - invalidate `["session"]`

Prefer server-confirmed success before showing a success toast. If using optimistic UI, make rollback explicit and test failure behavior.

## 11. Import and Official Data Pipeline

UI import:

- Route: `src/routes/import.tsx`
- Admin-only
- Parses `.xlsx`/`.xls` in browser with `xlsx`
- Uses simple 8-column format:
  1. project name
  2. department
  3. `plan_id`
  4. budget 2566
  5. budget 2567
  6. budget 2568
  7. budget 2569
  8. budget 2570
- Validates file extension, max size, numeric budget, non-negative budget.
- Persists via `apiBatchImportProjects()` / `serverBatchImportProjects()`.

CLI official import:

- `scripts/load-official-projects.js`
- Recreates official hierarchy and project data from staging output.
- Links Excel text box annotations into `project_annotations.project_id`.
- Verify with:

```bash
npm run verify-annotation-links
```

Text box extraction/import supporting scripts:

- `scripts/extract-textboxes.cjs`
- `scripts/forensic-extract.cjs`
- `scripts/import-projects.cjs`
- `scripts/lib/textbox-lookup.cjs`

`scripts/extract-textboxes.cjs` preserves original `rawText` for traceability, but classifies against normalized text. Keep that behavior: XML entities are decoded, Thai digits are normalized, split year digits are joined, Thai intra-word spaces are compacted, and slash spacing is normalized before amendment parsing.

Sensitive generated import artifacts should stay untracked. Check `.gitignore` before adding any large or source-data-derived files.

## 13. Audit Logging

Table: `audit_events`

Supported actions:

- `create`
- `update`
- `delete`
- `import`
- `status_change`
- `login`
- `logout`
- `export`

Audit payload shape:

- `action`
- `entity`
- `entity_id`
- `before`
- `after`
- `timestamp`

Server-owned mutation audit should include:

- actor from session
- server metadata
- before/after where practical

Do not log secrets:

- No passwords
- No raw `DATABASE_URL`
- No session secrets

Known limitation:

- Write + audit insert are currently sequenced in the same server function but not wrapped in explicit SQL transactions everywhere. If compliance requires atomicity, convert critical writes to transactions or stored procedures.

## 15. Money and Budget Rules

This system stores money in baht.

Display rules:

- Raw data values are baht.
- Do not interpret imported numbers as thousands unless the import source explicitly documents that.

## 16. Database Safety

Never:

- Commit `.env`
- Print `DATABASE_URL` in final responses or docs
- Put `DATABASE_URL` into `VITE_*`
- Run destructive SQL without user approval
- Delete production data without a backup/rollback plan
- Bypass `requireAdmin()` for writes
- Hand-build SQL strings with user input

Prefer:

- Read current schema from `scripts/migrate.js`
- Use `npm run migrate` for schema setup
- Use narrow SQL changes
- Add audit logs for new mutations
- Use `SELECT` verification before and after data migrations
- Keep generated/large import artifacts out of git

## 19. Known Issues and Sharp Edges

- Google Drive can corrupt or block `node_modules` writes. Prefer a local runtime clone for dev server work when install fails.
- `node_modules.broken-*` may be leftover from failed install attempts and should not be committed.
- `src/routeTree.gen.ts` can be dirty after route changes/build. Treat it as generated.
- Thai text may appear mojibake in some shell outputs because of terminal encoding. Inspect in editor/browser when accuracy matters.
- Server errors should generally be thrown as `Response`, not plain `Error`, from server functions.
- If Vercel login fails, first confirm production env vars (`DATABASE_URL`, `SESSION_PASSWORD`) and that production Neon has `admin_users` seeded. The login page should now surface these setup issues as Thai messages instead of a generic failure.
- UI import supports simple 8-column format; full official workbook handling is CLI-oriented.
- Audit writes are not universally transactional with data writes.
- Request IP/user-agent are not captured in audit logs yet.
- `mock-data.ts` still contains fallback/sample helpers, but runtime DB data is authoritative.

## 20. Common Change Recipes

### Add a project field

1. Add column to `scripts/migrate.js`.
2. Update DB type in `src/lib/api.ts`.
3. Update `serverGetProjects` / `serverGetProject` query shape as needed.
4. Update create/update server functions.
5. Update `ProjectFormDialog.tsx`.
6. Update list/detail route display.
7. Add audit before/after coverage if mutable.
8. Run `npm run build`.

### Add an admin mutation

1. Define wrapper/type in `src/lib/api.ts`.
2. Add `createServerFn` mutation in `src/lib/server-fns.ts`.
3. Call `requireAdmin()`.
4. Validate input.
5. Perform SQL with tagged template parameters.
6. Insert audit event.
7. Call from route/component with TanStack Query mutation.
8. Invalidate affected query keys.
9. Test public user cannot perform it.

### Add a new dashboard chart

1. Extend `DashboardData` in `src/lib/api.ts`.
2. Compute data in `serverGetDashboard`.
3. Render in `src/routes/index.tsx`.
4. Keep chart labels Thai and compact.
5. Ensure click/filter behavior is consistent with existing dashboard.
6. Test at 1366x768.

### Add a new route

1. Create `src/routes/<name>.tsx`.
2. Export a TanStack `createFileRoute`.
3. Use API wrappers, not direct server-fn imports when a wrapper exists.
4. Update `AppLayout.tsx` nav if needed.
5. Run dev/build to regenerate route tree.
6. Do not hand-edit `routeTree.gen.ts`.

### Change budget formatting

1. Start with `formatBaht()` in `src/lib/mock-data.ts`.
2. Search all call sites:

```bash
rg "formatBaht|งบ|budget|ล้าน|พัน" src -n
```

3. Verify values in project list, project detail, dashboard, equipment, and exports.
4. Confirm low values do not get misleading compact units.
